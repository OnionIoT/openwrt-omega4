# Omega4 / Omega4+ on OpenWrt 25.12

The `omega4-openwrt-25.12-port` branches use plan44 OpenWrt `p44_25.12`
at `1b0c773ac7` (25.12.6) and external Linux `linux-stable-openwrt25`
at `245834464f06` (6.12.112), with Onion board and driver changes on top.
The toolchain is GCC 14.3.0; packages use APK instead of opkg.

## Build

Keep `openwrt-omega4`, `linux-stable`, and `omega4-kernel-packages` as siblings,
all on their 25.12 port branches. The SDK is needed for boot artifacts; its
configuration and pinned U-Boot source remain documented in the boot packages.
From `openwrt-omega4`:

```sh
cp feeds.conf.default feeds.conf
./scripts/feeds update -a
./scripts/omega4p/prepare-feeds.sh
./scripts/feeds install -a
cp omega4p_defconfig .config
# Use omega4_defconfig instead for the original Omega4.
printf 'CONFIG_EXTERNAL_KERNEL_TREE="%s"\n' "$(realpath ../linux-stable)" >> .config
# Set CONFIG_OMEGA4P_BOOT_SDK_DIR (or CONFIG_OMEGA4_BOOT_SDK_DIR) if the
# SDK is not at the default ../../ref/1103B-SDK location.
make defconfig
make -j21
```

`prepare-feeds.sh` fixes a virtual-package dependency in the pinned LuCI feed.
Use a fresh build workspace when possible. `CONFIG_BUILD_SUFFIX="openwrt25"`
separates target artifacts from 24.10, but host staging is shared. An existing
24.10 host staging tree can contain obsolete gnulib macros that prevent host
elfutils from configuring; a fresh host staging/build avoids that contamination.

The original Omega4 and Omega4+ retain distinct device IDs, DDR loaders, FIT
formats and NAND layouts. Do not interchange their boot artifacts or firmware.
The `omega4-boot` / `omega4p-boot` packages emit boot binaries, including env.img,
into the target output directory; they do not install a runtime package.

## Updating a provisioned board

Back up settings and the environment before migration. Transfer the matching
`*-sysupgrade.tar`, compare its SHA-256, and run `sysupgrade -T` before installing.
Use normal `sysupgrade` to preserve settings. Do not reflash env.img on a
provisioned board: it contains Ethernet identity and boot configuration.
APK replaces opkg; older IPK packages cannot be installed on this image.

## Driver changes

The external kernel retains the Rockchip DMA heaps, mailbox and RTC support.
The local feed adapts platform removal callbacks and V4L2 interfaces to 6.12,
and Wi-Fi callbacks to the 6.18.55 cfg80211 backports. Vendor camera/encoder UAPI
headers are retained. Camera buffer allocation uses videobuf2 DMA-contiguous
support, selected explicitly for the external drivers.

The vendor MPP power-domain idle helper is unavailable in upstream 6.12. The
RV1103B/RV1106B encoder node has no power domain, so the compatibility path
returns unsupported; validation must exercise actual hardware encoding.

Hardware validation results are recorded in DEVLOG.md and the workspace's
`upgrade-25.12/hardware` evidence directory. A successful build alone does not
establish camera, audio or original Omega4 hardware compatibility.

## Validation (22 November 2026)

Both board profiles build. Omega4+ passed settings-preserving upgrades from
24.10 and from 25.12, cold boot, Ethernet transfer/ping, Wi-Fi scanning, RTC,
NPU inference, hardware H.264 encoding and 96 MiB/eight-pattern memory testing
on A29C. The environment remained byte-identical; network options were preserved
with a new DHCP DUID generated by OpenWrt. The saved disabled Wi-Fi setting was
retained. Original Omega4 hardware, camera capture, audio and long-duration
stability remain unvalidated. NPU inference works at its configured clock, but
vendor OPP/DVFS helpers are absent and dynamic NPU frequency/thermal control is
not qualified. Existing bootloader binaries were kept during these upgrades.

No custom APK repository was published. The generated upstream repository URLs
are not a validated update source for this custom target/local feed. Use matching
locally built APKs; do not substitute stock kernel modules.
